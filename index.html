Hi! I'm Elitsa. I study how we evaluate language models, and in particular whether the automatic evaluators we increasingly rely on can actually be trusted. When a free-form answer can be right in a dozen different ways, or wrong in subtle ones, a single “correct / incorrect” label from an LLM judge hides a lot. My work tries to make those judgments more fine-grained, more interpretable, and harder to fool.

At Sofia University I work with Ivan Koychev and Preslav Nakov (MBZUAI). Most recently I spent the summer of 2026 at Google Zurich on a Search team, stress-testing the reliability of an LLM autorater used for AI Mode. Before that, I was a software engineering intern at Uber in Amsterdam, and since 2022 I've been a teaching assistant for algorithms and AI courses at FMI.

How Correct Is Your Answer? A Semantic Correctness Framework for Open QA Evaluation

Elitsa Yotkova*, Violeta Kastreva*, Petar Velkov, Hristo Boyanov, Dimitar Dimitrov, Ivan Koychev, Preslav Nakov

Findings of the Association for Computational Linguistics: EMNLP 2026

An eight-class taxonomy of how open-ended answers can be right or wrong, two new datasets, and CAP, an NLI-based metric that respects that ordering better than existing judges and similarity metrics.

arXiv PDF
Free-form answers from LLMs can be correct in many surface forms, and they can fail in very different ways: they may be incomplete, contradict the reference, add hallucinated content, or go along with a false premise. Standard judge-based and similarity-based metrics tend to blur these cases together. We propose a semantic correctness taxonomy with eight ordered classes that, for example, separates answers that are verbose but correct from answers that also contain hallucinations. We release CAP-Correctness, an 8.8k-example benchmark built from widely used QA datasets, and CAP-Statements, an 11k-example dataset for turning question–answer pairs into declarative statements for NLI. Finally, we introduce CAP (Context-Aware Precision), a reference-based metric that scores question-conditioned statements with bidirectional NLI. In a monotonicity test that checks whether a metric respects the taxonomy's ordering, CAP outperforms established baselines.

* Equal contribution

FMI_SU_Yotkova_Kastreva at SemEval-2026 Task 13: Lightweight Detection of LLM-Generated Code via Stylometric Signals

Elitsa Yotkova*, Violeta Kastreva*, Dimitar Dimitrov, Ivan Koychev, Preslav Nakov

Proceedings of the 20th International Workshop on Semantic Evaluation (SemEval 2026), co-located with ACL

A CPU-only detector of machine-generated code, built from length-robust stylometric features and a shallow decision tree, that beats fine-tuned code encoders such as GraphCodeBERT by +0.37 macro-F1.

PDF Code Dataset
SemEval-2026 Task 13 asks systems to detect machine-generated code across programming languages and application scenarios, including languages and domains not seen during training. For Subtask A (binary classification), we compare pretrained code encoders with lightweight feature-based approaches. We design ratio-based stylometric features that are less sensitive to snippet length, and use parsers and a programming-language classifier to extract signals about how descriptive the code is. We also train a separate line-level classifier that finds natural-language text embedded in code samples. A shallow decision tree combined with rules derived from data analysis produces the final predictions. The approach trains on CPU only and runs inference almost instantly, making it a lightweight alternative to large pretrained models.

* Equal contribution
